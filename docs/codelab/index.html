QNX SDP 8.0 · ChannelCheck

From a resource manager to a clean image

Six steps. Steps 1–5 need Node 22. Step 6 needs QNX SDP 8.0 and QEMU. The long form is docs/CODELAB.md. The same lesson is the Codelab tab in the workbench. This page does not show output from qcc, because the host that checked ChannelCheck does not have the SDP installed.

Step 01

Write a QNX 8.0 resource manager

Create the channel with _NTO_CHF_FIXED_PRIORITY. Hand that channel to dispatch_create_channel. Attach a path with resmgr_attach. Transition with secpol_transition_type. Check every return. In io_devctl, iofunc_devctl_default only validates the message. Read ctp->info.cred or call secpol_check before you change device state.

chid = ChannelCreate(_NTO_CHF_FIXED_PRIORITY);
if (chid == -1) return EXIT_FAILURE;
dpp = dispatch_create_channel(chid, 0);
id = resmgr_attach(dpp, &resmgr_attr, "/dev/telemetry", _FTYPE_ANY, 0,
                   &connect_funcs, &io_funcs, &attr);
secpol_transition_type(NULL, "telemetry_t", 0);

Step 02

Pair it with an IFS buildfile

The bootstrap starts with startup-* and ends with procnto-smp-instr. PATH= becomes _CS_PATH, so do not leave . in it. The [+script] is not a shell. A command without & blocks the rest of the script. Call secpolpush before any daemon. Launch long-running processes with on -T. Leave ksh and qconn out of a production image.

[virtual=x86_64,bios +compress] boot = {
    startup-x86
    PATH=/proc/boot:/bin:/usr/bin procnto-smp-instr
}
[+script] startup-script = {
    secpolpush
    on -T telemetry_t telemetry_rm &
}

Step 03

Write a least-privilege secpol

Declare the types you launch. allow_attach names the path. allow client server:channel connect is the rule a MsgSend needs. Do not grant PROCMGR_AID_ROOT, mem_phys, or able_priv to an ordinary daemon. A wildcard allow is not a policy.

type telemetry_t;
type telemetry_client_t;
allow_attach telemetry_t /dev/telemetry;
allow telemetry_client_t telemetry_t:channel connect;

Step 04

Plant a deadlock and a privilege leak

Open examples/adas-sensor-bus. sensor_rm and fusion are single-threaded resource managers. Each io_devctl opens the other path and calls MsgSend. MsgSend waits for MsgReply, and the only thread that can reply is blocked in that send. The policy grants fusion_t root, and the buildfile runs secpolpush after ksh.

fd = open("/dev/adas/fusion", O_RDWR);
MsgSend(fd, &frame, sizeof frame, &frame, sizeof frame);

Step 05

Catch it with ChannelCheck

Scan the sample. The graph shows the cycle. Apply safe fixes. One MsgSend becomes MsgSendPulse, channels gain fixed priority, secpolpush moves up, and the root abilities disappear. Scan again. Critical findings are gone. ci exits 1 on the broken image and 0 on the hardened baseline.

npx channelcheck scan examples/adas-sensor-bus
npx channelcheck fix examples/adas-sensor-bus --dry-run
npx channelcheck ci examples/adas-sensor-bus
npx channelcheck ci examples/hardened-baseline

Step 06

Build and boot on QNX SDP 8.0 QEMU

Source qnxsdp-env.sh. The Makefiles use qcc -Vgcc_ntox86_64, qcc -Vgcc_ntoaarch64le, secpolcompile, and mkifs. The x86_64 image is a BIOS disk. The aarch64le image is a raw kernel. The shell scripts stop if qcc is missing, which is the honest behavior on a machine that only ran the analyzer.

. /opt/qnx800/qnxsdp-env.sh
make -C examples/adas-sensor-bus CPU=x86_64
make -C examples/infusion-pump CPU=aarch64le
sh scripts/qemu-x86_64.sh examples/adas-sensor-bus/adas.ifs
sh scripts/qemu-aarch64le.sh examples/infusion-pump/pump.ifs

Verified on the Linux host: the TypeScript engine, the tests, the CLI, and the workbench build. Not verified here: a QEMU serial console, because qcc is not installed in that environment.
